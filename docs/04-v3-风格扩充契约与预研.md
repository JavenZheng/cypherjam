# v3 · 十组 pattern、可插拔风格包、swing 导出修复与 Trap 预研

> 本文记录 v3 的四件事：数字键扩到 10 组、风格包数据化、Jazz swing 写进 WAV、Hip Hop / Trap 技术预研。
> 代码入口仍是 `app/index.html`，Tone.js 15.1.22（MIT，本地 `app/vendor/Tone.js`）。

## 一、十组 pattern：1–4 主段落，5–0 工具与变体

### 1.1 键盘与分组

| 键 | 序号 | 分组 | 用途 |
|---|---|---|---|
| `1`–`4` | A–D | **CORE** | 主段落，现场反复使用的核心 groove |
| `5`–`9` | E–I | **TOOLS** | 工具：roll、纯鼓、过门、和声块等 |
| `0` | J | **TOOLS** | 第 10 组，breakdown / outro / walking bass |

- 每种风格固定 **10 组，上限 10**，不再增加。
- `Space`、`B`、`S`、`Z X C V N`、`R` 全部保持原行为。
- UI 分两排：`.pattern-row[data-group="core"]` 绿色左边线，`[data-group="tool"]` 蓝色左边线；每排有 `CORE · 主段落 · 拿來放` / `TOOLS · 工具與變體 · 拿來轉` 标题。按钮本身也有 `data-group`，active 状态按组用绿/蓝高亮。
- 同风格内每个 pattern 的编辑仍然独立；切走再切回由 `styleCache` 保留；运行中切换仍落在小节线。

## 二、风格扩充契约（本版最重要的架构工作）

### 2.1 核心原则

一种风格 = **一包纯数据 + 一个 pattern 生成函数**，不包含 DOM、事件监听或引擎实例：

```
STYLE_PACKS 数组 → validateStylePack() → normalizePack() → STYLES
                                      ↑ 不通过就直接拒绝注册
```

UI 的风格按钮、pattern 按钮、编号、分组、BPM、swing、鼓组/合成参数全部从包读取，不再写死。新增曲风 = 往 `STYLE_PACKS` 里加一项；`app/index.html` 的其他位置不需要改。

当前仍是单文件实现，「可插拔」指**数据驱动注册**，不是运行时加载外部文件。包本身没有副作用，后续可以原样搬到独立 JS 模块。

### 2.2 必填字段

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | string | 字母/数字/连字符；全局唯一 |
| `label` | string | 界面显示名，如 `HIP HOP` |
| `bpm` | number | 60–200 |
| `patterns` | `() => Record<string, Pattern>` | 最多 10 组；键为 `A`–`J`；每次调用返回全新对象 |

`Pattern` 必须包含 7 条长度 16 的数组：`kick`、`clap`、`hat`、`bass`、`stab`、`atmos`、`sample`。
- `kick/clap/hat`：`0` 关、`1` 轻、`2` 重。
- `bass`：`{ note, dur, vel }`。
- `stab`：`hookEvt(...)` 或 `chordEvt(name)`。
- `atmos`：`padEvt(...)` 或 `airEvt(...)`。
- `sample`：`0/1`，播放导入的 one-shot。

### 2.3 可选字段与默认值

| 字段 | 默认 | 说明 |
|---|---|---|
| `swing` | `0` | 0–1；>0 时 `swingSub` 必须合法 |
| `swingSub` | `'16n'` | 只能是 `32n / 16n / 8t / 8n / 4n` |
| `names` | `{}` | `{A:'GROOVE', ...}`，缺省显示空 |
| `groups` | 前 4 个 core，其余 tool | `{core:['A','B','C','D'], tool:[...]}`；core 最多 4 个 |
| `mix.groupGains` | drums 1 / bass .68 / stab .55 / atmos .34 / sample .78 | 每条总线的基础音量 |
| `drums.kick/clap/hat/impact/boom` | Tech House 参数 | 音高包络、噪声类型、音量、滤波 |
| `synth.bass/stab/hook/pad/air/riser` | Tech House 参数 | 振荡器、滤波、包络、chorus、共振峰 |
| `harmony.scalePc` | A 自然小调 | **不允许改**，见 2.4 |
| `harmony.chords` | 内置 `CH` 表 | 和弦名 → 音名数组 |
| `harmony.insertChord` | `'Am'` | 空格点 CHORD 时插入的和弦，必须存在于 `chords` |

所有可选字段用两级深合并继承默认值；数组和函数整体替换。

### 2.4 锁调性：新风格为什么破坏不了

`validateStylePack()` 在注册时同步执行，任何一条不通过都会：

1. 把包从 `STYLES` 中剔除；
2. 写入 `STYLE_ERRORS`；
3. `console.error` 输出具体原因；
4. `__cj.validateStyles()` 返回 `ok:false` 与错误列表。

校验项：

- `harmony.scalePc` 必须与全局 A 自然小调 `[9,11,0,2,4,5,7]` 完全一致。此版采样自动调音 `nearestAMinorMidi()` 与 live pads 都硬绑定 A 小调，声明别的调会被拒绝，而不是「看起来能跑但采样跑调」。
- `harmony.chords` 里每一个和弦的每个音，pitch class 必须在 `scalePc` 内。
- `harmony.insertChord` 必须存在于 `harmony.chords`。
- `patterns()` 生成结果中：bass 音、hook 音、stab 和弦、pad 和弦全部做同样的 pitch class 检查。
- pattern 数量 ≤ 10，每条轨道长度必须 16。
- `id` 重复直接拒绝。

因此，新风格只要写了调外和弦（例如 `G#dim`），应用启动时就会被拒收，不会污染锁调性检查，也不会影响已有风格。

> 若要支持别的调，必须同时改 `nearestAMinorMidi`、live pads 音高表和 UI 文案——这是 v4 之后的事，本版明确不支持。

### 2.5 新增一种曲风的步骤

1. 在 `STYLE_PACKS` 增加一项：`id/label/bpm/patterns`。
2. 写 `patterns()`，返回 A–J（最多 10 组），默认留白。
3. 补 `names` 与 `groups`（不写则前 4 个自动为 core）。
4. 只写需要差异的 `drums` / `synth` / `mix`，其余继承默认。
5. 打开页面执行 `__cj.validateStyles()`，`ok:true` 即通过。
6. 不需要改键盘、按钮、BPM 逻辑或引擎初始化代码。

### 2.6 切换时的音频重建

鼓组与合成参数现在是包的一部分，切换风格时：

1. 先把当前 pattern 存回 `styleCache`；
2. `setTempo()` 改 BPM / swing / `STEP` / `BAR`；
3. 旧引擎 `dispose()`（统一释放所有登记节点，含 riser 噪声源）；
4. 用新包重建引擎，重连相同的总线结构，重新应用当前 filter / send / mute / solo；
5. 重建 pattern 按钮并复位到 A。

播放中切换会在下一拍使用新引擎，不中断 Transport。录音日志同时保存 `styleId`，离线渲染按该包重建，不会串音色。

## 三、Jazz swing 写进导出 WAV（缺陷修复）

### 3.1 根因

现场播放走 `Tone.Transport`，swing 偏移由 Transport 的 `_processTick` 施加；导出走 `renderLog()`，只按 `i * stepSec` 的绝对时间重放，日志里也没有 swing 信息，所以现场摇摆、导出是直的。

### 3.2 复现 Tone 的 swing 公式

Tone.js（PPQ 192）对每个 tick：

```
swingTicks = 该 swingSubdivision 的 tick 数（16n = 48）
period     = 2 * swingTicks
若 tick % 192 == 0 → 不偏移
若 tick % period == 0 → 不偏移
phase = (tick % period) / period
offsetTicks = sin(phase * π) * swing * (2 * swingTicks / 3)
offsetSec   = offsetTicks / 48 * stepSec
```

16 分 swing 下，每个奇数 16 分被延后 `(2/3) * STEP * swing`，偶数 16 分不动。Jazz 的 `0.35` 在 124 BPM 下约 **28 ms**。

### 3.3 修改

- `snapshotLog()` 新增 `swing`、`swingSub`、`styleId`；`testRender` 的日志同步。
- `renderLog()` 用 `tOf(rel) = rel * stepSec + swingOffsetSec(startStep + rel, swing, swingSub, stepSec)`，所有步进、build 释放点、slam 静音/重击都改用 `tOf`。
- `startBuild()` / `slamMute()` 增加 `stepSec` 参数，跨 BPM 录制时也用日志当时的步长。
- 保留 `__cj.swingProbe`：记录每步真实调度时间，供回归测试。

### 3.4 实测

- 实时 probe（Jazz，124 BPM，swing .35）：step 0→1 = **0.1492 s**，step 1→2 = **0.0927 s**，与公式完全一致。
- 离线渲染（只放 hat 的自定义日志）：检测到的 onset 间隔为 `0.156 / 0.091 / 0.148 / 0.092 ...`，交替出现；与期望时间的最大误差 **6.5 ms**（检测帧 4 ms 带来的偏差）。直拍应该是均匀 121 ms，因此可以确认 swing 已进入 WAV。
- 三风格离线渲染均正常：tech peak .64 / 5.78 s，deep .58 / 5.93 s，jazz .57 / 5.87 s。

### 3.5 仍存在的限制

- **录制中途切风格**：日志只有一份 `styleId`/`swing`，离线会用最后一次风格重放早先的步骤。声音可能不一致；本版建议录制期间不切风格。
- swing 只影响 16 分调度与过渡点；采样轨仍按整段 one-shot 从该步开始播放，不做时间伸缩。

## 四、Hip Hop / Trap 技术预研（只写结论，不实现）

### 4.1 808 低音 + pitch glide

**能不能做：能，但需要新增一种声部类型，不能只靠 pattern 数据。**

- 现有 `bass` 轨是 `Tone.MonoSynth` 的 one-shot：每一步 `triggerAttackRelease`，音头重新起包络。808 需要长衰减正弦、音符之间滑音（legato glide），这是「跨步状态」，与当前「每步独立事件」模型冲突。
- 可行做法：
  1. 新建 `Tone.MonoSynth` 808 voice：`oscillator: sine`、长 `release`、`portamento` 设 0.1–0.3 s，用 `triggerAttack` + `release`（而不是每步 `AttackRelease`）保持振荡器连续；
  2. 或在每步事件里记录 `glideFrom` / `glideTo` / `glideTime`，由 voice 在 `time` 上对 `frequency` 做 `setValueAtTime` + `rampTo`；
  3. 调度仍走 `scheduleRepeat`，但事件需要「持续/连奏」语义。
- 障碍：
  - 日志模型是 16 步 one-shot，不记录「音符是否连到下一步」，离线重放无法还原 glide；需要给 `bass` 事件增加 `tie/glide` 字段并在 `snapshotLog` 保存。
  - `MonoSynth` 的 portamento 是否在离线/实时两条路径完全一致需要实测。
  - 808 长尾会与 kick 的低频重叠，现有「kick 触发压 bass」侧链要加深，甚至需要分频处理（Tone.js 没有原生多段压缩，需自己拆低/高频两路）。

**结论：架构可扩展，主要工作量在「跨步连奏事件模型」与日志重放，不是合成器本身。**

### 4.2 三连音 hi-hat roll

**能不能做：当前不能直接表达，需要改调度/数据模型。**

- `Tone.Transport.scheduleRepeat` 固定 `'16n'`，`STEP` 与 `BAR_STEPS=16` 贯穿网格、键盘、录音日志、离线渲染。一拍三连音意味着每小节 12 个位置（或在一拍内 3 个非整数位置），现有 0–15 整数槽位无法表示。
- 可行做法：
  1. 在 hat 的每个 16 分槽位增加 `roll` 元数据（例如 `roll: { division: 3, count: 3 }`），调度时在 `time + k * (STEP/3)` 触发同一 hat；日志保存该元数据即可离线复现；
  2. 或单独开一个 `'8t'` 的 `scheduleRepeat` 通道，但会引入第二套步进计数，和现有「每 16 步一行」的日志/网格不一致。
- 障碍：
  - 网格 UI 需要标出「这一格里有三连击」，否则用户看不出来；
  - 键盘/录音日志/离线渲染都要携带子步信息；
  - Tone 的 swing 对 `8t`/`16n` 是全局设置，三连音 roll 与 swing 同时使用会叠加，需要明确优先级。

**结论：推荐方案 1（槽位内 roll 元数据），不引入第二条 Transport；工作量集中在数据模型与 UI 标记。**

### 4.3 Half-time（半拍感）

**能不能做：能，现有架构零改动。**

- half-time 只是 pattern 数据：kick 落在 0/8，clap 落在 8 或 12，hat 仍走 16 分；`scheduleRepeat` 不需要改。
- 已有 DUB / BREAK 类 pattern 就是这个思路，可直接作为 Hip Hop 模板。
- 与 swing 不冲突；与 808 长尾、侧链深度的配合需要在混音上单独调。

### 4.4 对下一版的排程建议

1. 先做 **half-time + 808 音色占位**（不改事件模型）验证听感；
2. 再做 **808 glide**：给 bass 事件加 `glide/tie`，扩展日志与离线重放；
3. 最后做 **三连音 hat roll**：给 hat 槽位加 `roll` 元数据，同时改网格标记与日志；
4. 低频管理：在 808 与 kick 共存时，先加深 sidechain，再评估是否需要分频处理；
5. 新增 `HIP HOP` 风格包时，按本文第二节契约注册，调性仍锁 A 小调，10 组 pattern 上限不变。

## 六、v4 引擎扩展与转场契约

> v4 给风格包增加四项**可选**能力：`half-time` 感知、808 `glide/tie`、hat `roll` 子步、BPM 转场。
> 四条铁律：锁 A 小调、调度器只有一条、现场与离线共用同一渲染、未声明的能力不改变播放路径。

### 6.1 能力是「选配」，不是全局升级

| 能力 | 声明位置 | 未声明时的行为 |
|---|---|---|
| half-time | `pack.feel = 'half-time'`（缺省 `straight`） | 播放路径完全不变，仅品牌栏不显示 `HALF-TIME` |
| 808 glide / tie | bass 事件字段 `glide` / `tie` | 走原 `triggerAttackRelease`（House 三种风格即此路径） |
| hat roll | pattern 的 `hatRoll[16]`（`0 / 3 / 4`） | `hatRoll` 全 0，hat 触发逻辑与改动前一致 |
| BPM 转场 | 演出层（TRANSITION），非风格包字段 | 不触发转场时，BPM 仍是各风格固定值 |

- `feel` 只是数据声明：半拍感由 pattern 位置表达（kick 落 0/8，backbeat 落 8 附近），**不加调度层**，BPM 不砍半。
- `hatRoll` 是**子步元数据**：在第 s 步内按 `k * stepSec / n`（k=0..n-1）补击打，仍然只有一条 `Tone.Transport` 与一个 `scheduleRepeat`。
- bass 的 `glide` / `tie` 由 `linkBass()` 展开为自包含字段，离线日志不需要「看下一步」：
  - `glideTo` / `glideSteps` / `glideIn`
  - `tieSteps` / `tieIn`
  - `holdsNext`（本颗不释放，由下一颗接续，避免衔接处断音）
- 锁调性校验同时覆盖 `bass.note` 与 `bass.glideTo` 的 pitch class，任何调外音都会让整包被拒绝（`validateStylePack` 返回错误，风格不注册）。

### 6.2 参数归属（写死，不靠「记得归零」）

| 类别 | 参数 | 风格切换时 |
|---|---|---|
| **风格专属** | `bpm`、`swing`、`swingSub`、`feel`、`hatRoll` 语义、鼓/合成器音色、pattern 数据、和声表 | **一律重设**，由新风格包决定 |
| **用户表演** | `filter`、`reverb`、`delay`、`sidechain`、各轨音量、`mute`、`solo`、当前 pattern 选择 | **必须保留**；切换后按原值重新 apply |
| **待切状态** | staged 目标风格、转场进度 | 取消时完全回滚到切换前 |

实现约束：`selectStyle` 重建引擎后重新 `applyParams` / `applyMix`；pattern 选择按字母保留（新风格存在同字母则保留，否则回落 `A`）。

### 6.3 TRANSITION：一次转场，不是两个功能

播放中按风格键**不立即切换**，进入 staged 状态并在品牌栏明示（`→ 待切`）；`T` 触发一次性转场，时长默认 8 小节、可设 2 / 4 / 8：

1. **降编**：降到 breakdown（只留 kick / clap / hat）；
2. **推速**：在稀疏状态下把 BPM 从当前值线性渐变到目标值（不瞬跳）；
3. **换风格**：到达目标 BPM 后切换风格包（音色、pattern、swing 一并重设）并触发一次落点重击；
4. **回编**：切换后按目标风格的满编继续，直到转场窗口结束。

分段（默认 8 小节）：降编 1 小节 → 推速 4 小节 → 换风格 1 小节 → 回满编 2 小节。4 小节档为 1 / 2 / 1，2 小节档为 0 / 1 / 1（没有独立降编小节）。

规则：
- 取消：staged 阶段再按同一风格键或 `Esc`，完全回滚；已开始但**尚未换风格**时 `Esc` 会把 BPM 沿剩余小节推回原值，换风格后不可取消。
- 转场进行中按其它风格键：**替换目标**（不叠加第二个转场），剩余推速曲线从当前 BPM 重算；已进入回编阶段则忽略。
- 非播放状态按风格键：立即切换（硬切允许，不算演出）。
- 切换时机只落在小节线，绝不切在拍中间。
- 参数归属沿用 §6.2：转场全程保留 `filter / reverb / delay / sidechain / 音量 / mute / solo / 当前 pattern 选择`；`BPM / swing / roll / 音色` 在换风格时由新风格包重设（降编与推速阶段 swing = 0、roll 关闭、glide/tie 停用）。
- 转场中 BPM 每步更新一次（8 小节档约 0.1 BPM/步），听感连续，且每步时长可被日志精确记录。

### 6.4 转场可录、可导出

**转场属于演出层，也必须进入可导出的日志**。录到的是一整场 set，不是没有转折的 loop。

日志新增字段（向后兼容，旧日志缺失时退回单步固定值）：

| 字段 | 内容 | 用途 |
|---|---|---|
| `stepSecs[]` | 每个 16 分步实际时长 | 推速期间逐步变化；导出按累计时间重放 |
| `styleIds[]` | 每个 step 实际风格 | 导出按风格切分连续段，每段用对应风格包建离线引擎 |
| `swings[] / swingSubs[]` | 每个 step 实际 swing 值 | 转场降编时录到 0，换风格后录到新风格值；离线按该步值施加偏移 |
| `transitions[]` | `{type:'style', step, bars, fromStyle, toStyle, fromBpm, toBpm, switchStep, endStep, canceled}` + `{type:'impact', step}` | 时间轴事件，供人读与校验；`impact` 在导出时重放落点重击 |

导出实现（`renderLog`）：

1. 用 `stepSecs` 求每步绝对时间：`t_i = Σ stepSecs[0..i-1] + swingOffsetSec(全局步号, swings[i], swingSubs[i], stepSecs[i])`；
2. 按 `styleIds` 切成连续段；每个出现过的风格各建一个离线引擎；
3. 每个 step 用其所属风格的引擎触发，`triggerStepData(..., stepSecs[i])`；
4. 转场 `impact` 在对应时间补齐；`style` 事件本身不再额外动作（风格已由 `styleIds` 重放）。

这样现场与导出的时间轴一致：**不存在「现场有转场、导出没有」或「现场滑、导出不滑」**。

#### BPM 渐变期间的时序风险

| 风险 | 处理 |
|---|---|
| 已排入未来的音符跑位 | 调度器只预排下一个 tick（lookAhead 0.1 s）；转场每步只改**下一步**的 `STEP`，不回溯已调度事件 |
| swing 偏移 | 降编 + 推速期间 `swing = 0`；日志逐步记录 `swings`，换风格后恢复新风格值 |
| roll 子步 | 降编 + 推速期间 `hatRoll` 强制 0（`stepDataOf` 剥离），避免子步时长随 BPM 抖动；日志记录的是剥离后的数据 |
| 808 长尾 / glide | 降编 + 推速期间 bass / stab / atmos / sample 全部移除，bass 链停止；日志同样记录为空 |
| 离线导出 | 每步 `stepSecs` / `swing` / `styleId` 都落盘，导出逐帧重放；采样率可选（见下） |

#### WAV 体积

16-bit 立体声 PCM：

| 时长 | 48 kHz | 44.1 kHz |
|---|---|---|
| 1 分钟 | ≈ 11.5 MB | ≈ 10.6 MB |
| 10 分钟 | ≈ 115 MB | ≈ 106 MB |
| **30 分钟** | **≈ 345 MB** | **≈ 317 MB** |

- 默认跟随浏览器的 AudioContext 采样率；REC 面板可选 WAV 48 kHz / 44.1 kHz。
- 采样率与实时上下文不同时，离线渲染会在离线上下文中重建混响 IR，避免 ConvolverNode 采样率不匹配。
- 30 分钟的 set 是数百 MB 量级，浏览器下载可行但不宜再叠加无损格式；需要更小体积时应改用实时 WebM/Opus 回退路径（音质与「离线渲染优先」不同，需明确标注）。

### 6.8 顺带修复：点亮格子的左侧缺口

**现象**：网格第 5 / 9 / 13 格（`data-step=4/8/12`，即每拍第 2 个十六分）点亮时，左缘出现一条很小的暗色缺口。

**根因**：`.cell` 使用 `box-sizing:border-box`，而拍点分隔线写成 `border-left:2px solid #2b3548`。border 占据盒子内部 2px，且 `.cell[data-step="4"]` 的属性选择器与 `.cell.on` 同权重但排在后面，覆盖了点亮状态的 `border-color`，于是点亮格左缘被画成 2px 深色边。

**修复**：移除 border，改用 `::before` 在格子**外侧**的 5px 列间距里画 2px 分隔线（`left:-4px`），不参与格子布局，也不再覆盖 `border-color`。

**验证**：TECH / DEEP / JAZZ 三风格 × 视口 900 / 1280 / 1600 × DPR 1 / 2，`data-step=4/8/12` 点亮格 `border-left` 均为正常的 `1px`，`::before` 为 `2px @-4px`；截图确认左缘完整。`×3` / `×4` 滚奏标记为格内居中文本 + `::after` 角点，不受该边框影响；修复后居中区域不再被 2px 吃掉。Trap / Hip Hop 加入后再复检同位置。

### 6.9.1 Trap 速度复检与 half-time 重写（2026-11-07）

**反馈**：用户认为「Trap 速度太快，Trap music 不會這麼快」。先量测再判断，不改 BPM。

**量测方式**：无头 Chromium 实时播放；`swingProbe` 记录 Transport 每一步的真实调度时间，另在 `Tone.NoiseSynth` / `Tone.MembraneSynth` 的 `triggerAttackRelease` 上打点，记录 hat / kick 的真实触发时间。全部用实际时间戳算间隔，不用设定值回推。

| 量测项 | TRAP 145 BPM | TECH 127 BPM | 理论值 |
|---|---|---|---|
| 一格（16 分） | `0.10345 s`（min=max，比值 1.0000） | `0.11811 s`（min=max，比值 1.0000） | 0.10345 / 0.11811 |
| 一小节（16 步） | `1.65517 s` | `1.88976 s` | 1.65517 / 1.88976 |
| kick 相邻间隔（half-time） | `0.82759 s`（= 8 步，感知 72.5 BPM） | 0.47244 s（4 步，127 BPM） | — |
| hat 常规相邻间隔 | `0.10345 s`（16 分） | 0.47244 s（4 步） | — |
| hat roll 子步 | `0.03448 s`（×3）/ `0.02586 s`（×4） | 无 | `STEP/3` / `STEP/4` |

**判断**：调度层没有 bug。145 BPM 的 16 分步长与小节长度与理论值完全一致，hat、kick 的实际触发间隔也等于对应步数。用户听到的「快」来自 pattern 写法，而不是时序：

- 旧 `B BOUNCE` kick `[0,6,8,14]`、旧 `D DROP` kick `[0,4,8,11]`，每小节 4 颗 kick，实际把耳朵拉到 145 BPM；
- 旧 `C ROLL` 每小节 4 组三连音 roll（`2/6/10/14`），加上全铺 16 分 hat，活动量过密；
- 旧 808 通过 `linkBass` 的 `glide/tie` 吸收后常驻整小节，没有呼吸点。

**修正**：

- `A/B/C/D` 全部改为 half-time 骨架：kick 只在 `[0,8]`，clap 只在 `[8]`，其余留白；16 分 hat 保留（Trap 的密集感在 hat，不在 kick）。
- `B BOUNCE` 的弹跳交给 808 滑音（A1→C2、A1→E2），不再用抢拍 kick；`D DROP` 的 808 改为 A1→E2 的长音，收尾后留白。
- `C ROLL` 的 roll 从 4 组减到 `6/14` 两组，保留 `15=×4`；`E 808 ONLY` / `I GLIDE` 同步减为 2–3 个落点。
- 808 收尾刻意留白（A/C/G 在 8 后 0.45–0.5 s 释放；D 在 8 后 0.5 s 释放），不再整小节常驻。
- 品牌栏对 `feel:'half-time'` 的包同时显示写实与感知 BPM：`TRAP · 145 BPM · A MINOR · FEEL 72.5 · ONE-PERSON DJ`。

**修正后实测**：A/B/C/D 的 kick 相邻间隔均为 `0.82759 s`；A/B/C/D 的 `kickSteps=[0,8]`、`clapSteps=[8]`；`validateStyles` 通过；Trap 2 小节离线 `5.31034 s`（含 2 s 尾巴），`chainBass=4`，无页面报错。三 House 回归时长不变：TECH `5.77952 s`、DEEP `5.93442 s`、JAZZ `5.87095 s`。

**未做（按用户要求先不做）**：130–135 BPM 的 modern trap 变体；两小节 32 步 pattern 结构（需改引擎，仅评估）。

### 6.9.2 Trap 改 Memphis 質感重做（2026-11-07）

**反馈**：用户澄清要的是 **Memphis rap**（参考 攬佬 SKAI ISYOURGOD《八方來財》），不是干净的现代 Trap；问题在质感，不在 BPM。要求把现有 Trap 包直接改成 Memphis，不并存两个 Trap。

**三个必要特征与实现**

| 特征 | 实现 | 关键参数 |
|---|---|---|
| 失真 808 | 正弦 808 → `Tone.Distortion`（内部是 WaveShaper，不依赖 AudioWorklet）→ 低通 → 高通 | `drive 0.7`、`lowpass 1050 Hz`、`highpass 22 Hz`、`pitchDrop 2`、envelope `decay 0.9 / sustain 0.25 / release 0.5` |
| 牛铃 Cowbell | 独立 `Tone.FMSynth` 轨（square×square，harmonicity 1.6，modulationIndex 9）+ 1050 Hz bandpass，接鼓组总线；无采样 | `volume -5`、`decay 0.075`、`dur 0.09` |
| 脏 lo-fi | 总线上串 `Tone.Filter`（7.8 kHz 低通）→ 8-bit `WaveShaper` 量化曲线 → `masterGain`；另叠 pink noise 底噪。全部不用 Worklet | `lowpass 7800`、`bits 8`、`noise 0.025`、`noiseLowpass 4200` |

### 6.9.3 Drill 风格包（2026-11-07）

**BPM 依据**：查证结果（2026-11-07）：UK drill 典型 141、整体 drill 典型 142，常见区间 138–145（se7en BPM Index、Tunely）。因此取 **142**，与用户「先取 142」一致；`140–145` 范围内可通过改 `bpm` 调整。

**与现有 Trap 的滑音差异**

| 项目 | Trap（Memphis） | Drill |
|---|---|---|
| 滑音时长上限 | `glideMax` 未设 → 默认 `0.28 s` | `glideMax 0.09 s` |
| 滑音起点 | 目标音前 0.28 s 开始滑 | 目标音前 0.09 s 才开始滑 |
| 听感 | 长滑、拖、糊 | 短、急、硬，滑完立刻落点 |

实现上只在引擎把原来的硬编码上限 `Math.min(0.28, steps*stepSec)` 改为 `Math.min(S.bass.glideMax || 0.28, steps*stepSec)`；其余 glide 链（`glideTo / glideSteps / glideIn / holdsNext`）不变，因此导出与现场仍是同一时间轴。

**音色参数（与 Memphis 的区分）**

| 项目 | Drill 取值 | 说明 |
|---|---|---|
| 808 失真 | `drive 0.35`、`lowpass 1400`、`highpass 25`、`pitchDrop 1.4` | 比 Memphis（0.7 / 1050）轻，干净但沉 |
| 808 包络 | `decay 0.85 / sustain 0.22 / release 0.45` | 不糊尾 |
| 鼓组压缩 | `Compressor threshold -22 / ratio 4` | 门控感 |
| kick | `pitchDecay 0.006`、`decay 0.045`、`volume -4` | 短促硬，低频让给 808 |
| snare（clap） | `volume -9`、bandpass `1600 Hz`、`decay 0.075` | 固定第三拍 |
| hat | `highpass 9500`、`decay 0.028`、`volume -12` | 只做点缀 |
| lo-fi | `lowpass 14500 / bits 0 / noise 0.008` | 比 Memphis（7800 / 8-bit / 0.025）干净；全部不用 Worklet |
| 和弦 loop | 三角波 stab，`volume -10`，只 Am / Em / Dm | 冷、暗、小音程 |

### 6.10 Humanize 实测（v4 阶段四）

**目标**：每颗音符有力度微变与前后的微时序偏移；界面可见、可一键回方正；进日志、导出 WAV 必须重现；每风格可选默认档位。

**实现口径**

| 项目 | 做法 |
|---|---|
| 档位 | `off / tight / natural / loose`，分别对应 `0 / ±3 ms·±4% / ±8 ms·±8% / ±15 ms·±12%`；界面只显示「OFF / 緊 / 自然 / 鬆」，不逼用户读毫秒 |
| 风格归属 | 风格包可选字段 `humanize`，缺省 `off`；切换风格时按新包默认值重设。当前四风格全为 `off`，Funk / Hip Hop 以后再设 `natural` |
| 确定性 | 偏移与力度由 32 位哈希 `humRand(step, lane, idx)` 决定，**绝不 `Math.random`**；`step` 是绝对步序号（现场 `globalStep`，离线 `log.startStep + i`），因此同一份日志任意时刻重放都落到同一时间点 |
| 作用范围 | kick / clap / hat / bass / stab（hook 与 chord）做时序 + 力度；pad / air 只做力度、不动时序；SAMPLE 轨是整段 one-shot，不做 humanize |
| roll 保护 | 滚奏子步间隔很短，偏移压到「子步间隔的 1/4」以内，避免连音错位；每轨另有单调守卫（相邻事件至少 `+1.5 ms`），防止 Tone 包络时间线倒序 |
| 日志 | `recState.hums[]` 逐步记录当时档位；`snapshotLog()` 输出 `hums` 与顶层 `humanize`；`renderLog()` 逐 step 还原 |
| 导出 | 离线渲染把 `{ level, step }` 传给引擎，与现场走同一个 `triggerStepData`，不存在两套节奏算法 |
| UI | PERFORM 面板 SIDECHAIN 下方新增 `HUMANIZE` 分段按钮；开启时品牌栏追加 `· HUMANIZE 自然`；**未新增任何键位** |

**无头 Chromium 实测（1360×920，DPR1）**

| 项目 | 结果 |
|---|---|
| 契约 | 四风格全部 `humanize:'off'`；非法值 `medium` 被契约拒绝：`humanize 只能是 off / tight / natural / loose` |
| 偏移范围 | 64 步采样：tight `-2.918…+2.949 ms`、natural `-7.780…+7.864 ms`、loose `-14.588…+14.744 ms`；同参数重复计算 64/64 完全一致 |
| 时序重现 | 纯 kick 日志：natural 起音位移 `+6.939 ms`（预期 `+6.959 ms`），loose `+13.039 ms`（预期 `+13.048 ms`），误差 ≤ 1 个采样 |
| 同档重放 | 同一档位两次离线渲染逐样本最大差 `4.1 × 10⁻⁵`；来源是 riser 噪声的随机相位（既有行为），不是 humanize |
| 现场录制 | 录 28 步后 `snapshotLog().hums` 长度 28，全部为当时档位 `natural`，与 `steps` 一一对应 |
| 三 House 回归 | OFF 下时长不变（TECH `5.77952 s` / DEEP `5.93442 s` / JAZZ `5.87095 s`）；DEEP / JAZZ `legacyBass=8`，TECH 默认 pattern A 无 bass 事件（设计留白） |
| 键位 | `Space` 仍切换播放/停止；按 `H` 无任何反应，未新增绑定 |
| 移动端 | 390 / 360 下 HUMANIZE 分段宽 306 / 278 px，右侧留白足够；`scrollWidth` 仍为既有的 `675`，本功能没有加重横向溢出 |

**已知限制**：clap / air 走 NoiseSynth，每次离线渲染的噪声相位不同，因此整段音频不可能逐样本完全一致；这是既有特性，与 humanize 无关。听感（紧/自然/松是否真的可感知）与真机长跑仍未由人耳验证。
