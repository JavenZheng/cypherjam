# 路線決策 · 2026-11-07

## 一、不按曲風分家

真正要分的不是「曲風」，而是兩種用戶任務：

| 任務 | 用戶在做什麼 | 需要的核心能力 |
|---|---|---|
| **放歌** | 在派對上撐場：選風格、推速度、轉場、堆疊、留白 | 鼓組時間軸、低頻、風格包、轉場、可導出的整場 set |
| **寫歌** | 坐下來寫一段音樂：和弦、旋律、即興 | 和弦進行、聲部、旋律編輯、樂句結構 |

因此**不按 House / Trap / Hip Hop / Jazz 分家**：

- **CypherJam = 放歌工具**：House（TECH / DEEP / JAZZ HOUSE 現階段都留在這裡）、Trap、Hip Hop、Funk。
- **第二個產品 = 寫歌工具**（Jazz / Swing，核心是和弦進行與即興）：**暫不啟動**，等派對實測後再決定。
- **Funk 歸到放歌這邊**：它要的是律動細節（人性化時序、ghost note、游移的微時序），不是和聲引擎。
- 若將來真的分家，做法是「**一套引擎、多個外殼**」，不是複製三份程式。
- 分家的觸發訊號：有人問「**能不能讓我自己做一段旋律**」，而不是「我覺得應該有」。沒有真實需求就不分。

## 三、Humanize 的邊界（先寫死，實作時照此驗收）

- 每個音符可帶 **velocity** 與 **微時序偏移**（前後幾毫秒到十幾毫秒）。
- 偏移在界面上**看得出、可關閉**；一鍵回到完全方正（全 0）。
- **與轉場同等對待**：進日誌、導出 WAV 必須重現，不得「現場有律動、導出變方的」。
- 每風格**選配**：House 默認關；Funk / Hip Hop 默認開。
- 不讓用戶自己填毫秒：給「**緊 / 自然 / 鬆**」三檔可感知預設。

**實作定案（2026-11-07，已落地）**：

| 檔位 | 時序偏移 | 力度 |
|---|---|---|
| OFF | 0 | 0 |
| 緊 | ±3 ms | ±4% |
| 自然 | ±8 ms | ±8% |
| 鬆 | ±15 ms | ±12% |

- 偏移由**絕對步序號 + 軌道 + 序號**的雜湊決定，**不用 `Math.random`**；現場與離線渲染走同一個函式，因此同一份日誌重放一定落在同一時間點。
- 每軌有單調守衛（相鄰事件至少差 1.5 ms）；滾奏子步的偏移再壓到子步間隔的 1/4，避免連音錯位。
- kick / clap / hat / bass / stab 做時序與力度；pad / air 只改力度；SAMPLE 軌不動。
- 日誌逐步記錄 `hums[]`（當時檔位），導出 WAV 逐 step 還原；這是「現場有律動、導出也要有」的實作保證。
- 介面只給 `OFF / 緊 / 自然 / 鬆` 分段按鈕 + 當前範圍提示，不新增鍵位。

## 四之二、Drill 的定位（本輪實作）

- **不是新模組，是 Trap 的低成本變體**：同一套引擎、同一組 `glide` / `hatRoll` / `linkBass` 能力，只換 pattern、鼓型與滑音走向。
- 簽名只有一個：**808 在音符之間滑動**（不是換音），滑音短而急。
- 與既有 Trap 的 `I GLIDE` 組差異：`I GLIDE` 是同一包裡的示範 pattern，滑音仍偏長、有 tie；Drill 整包都以短滑音為骨架，snare 固定第三拍，kick 切分。
- BPM 核實（2026-11-07）：UK drill 典型 141、整體 drill 典型 142，區間 138–145（se7en BPM Index、Tunely）。取 **142**；142 落在 140–145 的常見區間。
- 質感定位：比 Memphis 乾淨（無牛鈴、無 8-bit 量化、底噪更低），比 Metro 式 Hip Hop 更冷更硬（鼓更稀疏、808 滑音更尖）。
- **三者區隔**：Memphis = 失真重（`drive 0.7`）、808 長尾會糊（1.46 s）、牛鈴是記憶點、8-bit + 7.8 kHz lo-fi；Drill = 失真輕（`drive 0.35`）、808 滑音短而急（`glideMax 0.09 s`）、無牛鈴、乾淨（14.5 kHz / 無量化）、snare 固定第三拍；Metro 式 Hip Hop（暫緩）= 乾淨但極簡、808 巨大常駐、留白最多，靠低頻重量而非合成器簽名。

## 五、多軌音軌的邊界（Memphis / Drill 之後實作）

分兩類，**合計上限 8 條**，循環類不得超過 4 條：

| 類別 | 上限 | 是否佔格子 | 時間屬性 | 必要能力 |
|---|---|---|---|---|
| **A. Loop Clip** | 4 | 是（步進格） | 對拍、可循環 | 自動測長 → 建議最近小節數 → 接縫交叉淡化 + 播放速率微調（限 ±3%）；超限明確提示「對不上拍，建議重錄或手動裁切」，不硬拉；IN/OUT、淡入淡出、循環開關、獨立音量與濾波、格子內指定起始步 |
| **B. Ambient Bed** | 4（建議配置） | 否 | 自由長度，不跟 BPM | 獨立混音條：音量、淡入淡出、mute、play/stop；可多條疊放 |

**為什麼分開**：格子高度是手機可用性的硬限制。Loop Clip 有節奏屬性、需要步進定位，所以放格子；Ambient Bed 是連續鋪底，放格子純屬浪費空間。分開後 8 條也不會讓手機爆掉。

**不可退讓的實作約束**：

- 頁面內 **MediaRecorder** 直接錄麥克風，手機可用（權限提示、錄音中狀態、時長顯示）。
- 儲存方式（IndexedDB 或記憶體）與重新載入後是否還在，要如實寫明；四條各一分鐘立體聲的記憶體佔用也要寫明。
- 兩類音軌的播放都要**進日誌**、導出 WAV **必須重現 IN/OUT、淡入淡出、循環與起始位置**，不得「現場有、導出沒有」。
- **不改動既有鍵位** `Space / B / S / Z X C V N / R / T / 1-9 / 0`；新增 mute 鍵另給。
- 4 條 Loop Clip 是手機格子的上限，加入後要實測不擠。
- **實務提醒**：8 條同時響會糊。用可感知提示（電平表或「同時發聲軌數」）讓使用者自己判斷，**不要做成警示彈窗**。

**實作定案（2026-11-07，已落地）**

| 項目 | 定案 |
|---|---|
| 槽位 | 固定 4 個 LOOP + 4 個 AMBIENT，合計 8；沒有「再開一條」入口，上限是結構性的 |
| Loop 對拍 | 載入即測長 → `round(秒數 / 當前小節長)` 取 1–8 小節 → `rate = 段長 / (bars × 小節長)`；只有 `|rate−1| ≤ 0.03` 才套用，否則 `rate=1` 並提示「對不上拍，建議重錄或手動裁切」 |
| Loop 控制 | ON/OFF、IN/OUT（百分比）、FADE IN/OUT、VOLUME、LOWPASS、16 格 START STEP 小條（直接在格子內點起始步） |
| Loop 播放 | 跟 transport；到 `startStep` 才起播，之後由 `Tone.Player` 自身 loop；換風格／BPM 改變時重算 rate，並在最近的 `startStep` 重啟 |
| Ambient | 不佔格子、不跟 BPM、自由長度；PLAY/STOP 獨立於 transport，循環到按停；獨立的 FADE IN/OUT、VOLUME、MUTE |
| 錄音 | 頁面內 `MediaRecorder`（`getUserMedia`），單次上限 **60 s**，停止後 `decodeAudioData` → 峰值歸一到 0.94；選中哪個槽位就錄進哪個槽位 |
| 儲存 | **只存記憶體，重新載入即消失**；四條 1 分鐘立體聲 44.1 kHz float32 約 **92 MB**（未含解碼暫存），因此不做持久化 |
| 鍵位 | 不動既有鍵位；新增 **`M` + `1–8`**（1.8 秒內按數字）＝ LOOP 1–4 / AMBIENT 5–8 mute，`M` 本身沒有其他用途 |
| 混音位置 | 音軌匯流排接到 `engine.masterGain`，**不進 mixBus**：不參與側鏈、不被風格的 lo-fi 濾波降質，但會被 SLAM / drop 的硬切一起帶走；匯流排增益 0.65 |
| 日誌／導出 | 每步記 `trackSteps[]`（on/playing、startStep、IN/OUT、rate、gain、LPF、fade、mute），另存 `trackSnap`（AudioBuffer 與 bars）；離線渲染重建播放窗口，重現 IN/OUT、淡化、循環、起始步 |
| 手機 | 390/360 的 `documentElement.scrollWidth` 等於視口寬；`.grid` 放進可橫向滾動的 `.grid-wrap`（手機 cell 30 px），頂欄改為上下堆疊，不再撐破頁面 |

## 六、五種風格的「可辨識簽名」

判斷一個新曲風值不值得加，先問：**它有沒有一個 3 秒內聽得出來的簽名？** 沒有就先不加。

| 風格 | 簽名 | 一句話辨識 | 現況 |
|---|---|---|---|
| **TECH HOUSE** | 四方拍 + 短促 off-beat bass | 四拍落地、每拍都有東西 | 已上線 |
| **DEEP HOUSE** | 慢、沉、長和弦 pad | 拍子還在，但空間很大 | 已上線 |
| **JAZZ HOUSE** | 16 分 swing 0.35 + 七/九和弦 | 一聽就有搖擺 | 已上線 |
| **TRAP · MEMPHIS** | **牛鈴旋律 + 失真 808 + lo-fi 底噪** | 破、髒、牛鈴一直響 | 已上線 |
| **DRILL** | **808 短滑音 + snare 固定第三拍 + kick 切分** | 低音在音符間「滑」 | 本輪實作 |
| **Funk（巴西 baile funk）** | tamborzão 切分 + 喊答型人聲 | 切分密集、對方接話 | 候選，暫不做 |
| **Hip Hop（Metro 式）** | 空、沉、巨大 808 | 靠留白與低頻重量，**沒有合成器簽名** | 暫緩（見第七節） |

**這張表就是日後的路由器**：新曲風若說不出「3 秒內聽得出來的簽名」，先放候選，不要直接開工。

## 七、Hip Hop（Metro 式）為什麼暫緩

- **沒有可辨識的合成器簽名**：它的身分是「空、沉、大 808」，本質是**留白**，不是音色。留白做出來會像 demo，而不是像一首歌。
- **設計前提是留空間給人聲**：目前沒有取樣鼓、沒有人聲，純合成 fill 不出 Metro 的乾淨低頻質感。
- **回歸負擔**：每多一種風格就多一組 pattern、BPM、轉場與回歸測試；Drill 已能用既有 glide 低成本覆蓋「低頻重量」這一支。
- **若日後要做，先縮減規格**：
  1. 只做 **6 組 pattern**（不是 10 組）；
  2. 必須先有**取樣鼓**與**人聲/採樣能力**，否則不開工；
